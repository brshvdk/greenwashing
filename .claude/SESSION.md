## Known issues / traps
- Gate limits (also in the map): `node --test` counts a test file with no tests as one passing test; a test that prints a summary-like line adds counts; an agent can edit `.greenwashing.json` or `gate/` during the turn (Safety net guards only at PR level); a gate that cannot start (no `node` on PATH) fails open in Claude Code; `CATALOG.md` and `SKILL.md` count as documentation.
- Gate, open from the PR 4 review (each reproduced by the reviewer's runs; not fixed in PR 4):
  - change detection misses edits inside a submodule or a nested repository (git reports the folder, hashed by its mode), files git does not report (a gitignored `.env` the tests read, a project inside an ignored folder, `assume-unchanged`), a symlink to a file outside the repository and a permission-only change; a report file the tests rewrite (`junit.xml` not ignored) makes a test-only turn a code change.
  - counts: code under test that calls `process.exit(0)` makes a `node --test` file "1 passed"; `pytest.exit(returncode=0)` reads as passed; an agent that narrows the test script or leaves a `.only` gets green counts.
  - commands: runners outside the five (`go test`) always did not run, and `.greenwashing.json` has no way out; `pnpm -r` prefixes hide the counts; a venv not on the hook's PATH needs `testCommand`; a session started in a subfolder uses that folder's config while changes count repo-wide; a pytest project with no pytest config runs the unittest fallback (only `TestCase` classes); outside git only top-level `.py` files make a Python project (live: tests only in `tests/` -> allowed as "no test command").
  - one `git cat-file` per changed file (review: 20,000 files, 136 s); an explicit `jest --watchAll` still waits for the timeout under `CI=true`; the agent (same user) can edit the state file; a state folder the gate cannot write makes every Stop exit 2 until Claude Code's own cap; vitest `Tests  no tests` is did not run with the "no test counts" reason, not GW-08.
- Subagent worktrees (`.claude/worktrees/`) are nested repositories to git: each shows as one untracked folder entry, and tree walks must skip folders with their own `.git`.
