Map of the repository: only what exists now. All three product modules are here: the catalog, the skill and the gate (with its mutation command), the last two shipped as a Claude Code plugin from `plugin/`; the benchmark measures the gate.

## Modules

### CATALOG.md

Purpose: the public catalog - the ways a test suite goes green without the code being right. Data, not code. Sections `## A.` to `## H.`; each entry is a `### GW-NN Title` heading followed by exactly three list items in order: `- **Looks like:**`, `- **Why it's green:**`, `- **Catch it:**`. IDs are stable and never renumbered; gaps between sections are on purpose. The catalog is the only source of its entries: nothing else counts them or lists their numbers.

Tests: `tests/test_catalog.py` - the structure only, read line by line as Markdown splits lines: entry headings (ASCII number in one form, a title with an ASCII letter or digit), numbers unique and ascending, the three lines in order and each with an ASCII letter or digit, sections A-H in order and none empty, no entry outside them, and outside entries no line that starts like markup able to hide entries or move them under another heading (indented or quoted lines, HTML, code fences, headings other than a `# ` title on the first line, setext underlines); markup after a list marker or in the middle of a line is not checked. Mutants of the real catalog must report exactly the rules they break, valid variants none.

Depends on: nothing.

Breaks: `tests/test_catalog.py` (the structure is its contract); `tests/test_skill.py` (the skill cites entry numbers); the gate's block messages (cite GW-01, GW-08, GW-17, GW-18, GW-50 and GW-114; `tests/gate/verdict.test.js` checks each is an entry); the mutation command's report (GW-02, GW-04, GW-11 and GW-61; `tests/gate/mutants.test.js` checks the hints' entries); `bench/cases` (each case names an entry; `bench/run` refuses a number that is no heading); the links in `README.md` (entry headings as GitHub anchors; `bench/readme` checks them) and `docs/configuration.md`, and the link in `plugin/skills/greenwashing/SKILL.md`.

Traps:
- adding a section after H or changing the three lines - change `SECTIONS` or `FIELDS` in `tests/test_catalog.py` in the same PR, otherwise the test goes red.
- renumbering an entry - the test checks that numbers are unique and ascending, not that they stay the same, so a renumbering passes it.
- renaming an entry's title - its GitHub anchor changes: CI "README check" goes red for the README's links, while the links of `docs/configuration.md` (GW-01, GW-17, GW-18, GW-114) are not checked.
- inline HTML or an empty link inside an entry line or title - the test only asks for one ASCII letter or digit, so `&nbsp;`, `<!-- x -->` or `[](url)` passes and renders empty.
- writing outside entries - the markup rule is conservative: an autolink, inline HTML or `#1` at the start of a line, an indented or nested list, a GitHub alert (`> [!NOTE]`) and `---` turn the test red.
- touching line splitting in the test - keep CRLF, CR and LF only, otherwise (`str.splitlines`) U+2028, form feed and others split an entry that Markdown renders as one line.

### plugin/skills/greenwashing/SKILL.md

Purpose: the skill for coding agents that read the Agent Skills format: what to do before reporting "done" and how to report, citing catalog entries by `GW-NN`. Frontmatter `name` (the folder name) and `description`. Meant to be installed with `npx skills add brshvdk/greenwashing`: a live `skills@1.7.2` run on a working copy finds exactly this one skill in `plugin/skills/greenwashing/` and puts the file unchanged into the project's `.claude/skills/greenwashing/SKILL.md`. The field rules follow agentskills.io/specification.

Tests: `tests/test_skill.py` - frontmatter present (LF, CRLF or CR endings, a BOM allowed; one-line values, quotes removed, `~`/`null` read as empty; a block value `>` or `|` is reported, the checker cannot measure it); `name` equals the folder, only lower case letters, digits and hyphens, a hyphen only between letters or digits (none at the start or end, never two in a row), at most 64 characters; `description` not empty, at most 1024 characters; the skill cites at least one `GW-NN` and every one is an entry heading of `CATALOG.md`; the catalog's entry count does not appear in the skill. Mutants of the real skill must report exactly the rules they break.

Depends on: `CATALOG.md` (entry numbers, entry count).

Breaks: `tests/test_skill.py` (the frontmatter and cited numbers are its contract); the plugin (loads it from `plugin/skills/greenwashing/`, see below).

Traps:
- removing or renumbering a catalog entry the skill cites - `tests/test_skill.py` goes red; change the skill in the same PR.
- adding or removing a catalog entry - the forbidden number changes, so any bare number in the skill equal to the new count (`0.87`, `line 87`) turns `tests/test_skill.py` red.
- adding an entry numbered GW-19, GW-99 or GW-199 - `tests/test_skill.py` uses these as numbers missing from the catalog (`test_id_not_in_catalog`); pick another gap in the same PR.
- the skill links to `CATALOG.md` on `main` by URL - renaming or moving the catalog breaks the link, and no test checks it.

### gate (`plugin/gate/`)

Purpose: the Claude Code hooks that keep an agent from finishing a turn that changed code while the tests fail or did not really run. `node plugin/gate/hook.js prompt` (UserPromptSubmit) records the start of the turn - HEAD and a content hash of every file git reports as dirty - in the project's git tree and, when the agent is in another worktree of the same repository, in that one too, plus the commits the worktrees and branches of the repository point at; the state file sits in a per-user `0700` folder of the temp directory (one per session and project), used only while it is a folder, not a link, of the user's own that no one else can open (`stateFolder()`), and is read only as a plain file of one name (`readState()`) and written as a new `0600` file renamed into place (`saveState()`): never through a link. The start moves only when a Stop accepts the work (green tests, or no code changed): after an interrupted turn, a blocked one or one let go as "WORK NOT ACCEPTED", the next prompt keeps the starts, so the work the gate did not accept is measured again. Every prompt also records the gate's settings as they are then: the project's `.greenwashing.json` text, and the `.greenwashing.json` files of each tree (a snapshot of those files only), against which GW-114 is measured, so a human's edit between turns never blocks; every prompt and Stop records those files as the gate sees them (`stopped`), and at a prompt after a turn no Stop accepted, each file that differs from the turn before's snapshot but is still as the gate last saw it keeps its earlier state, in a tree that has such a snapshot, and the project's text with it (the agent's change carried over keeps blocking; a file changed since is the user's). `node plugin/gate/hook.js stop` (Stop) checks every tree the turn has seen - the project's, and every worktree of the repository that was the input's `cwd` at a prompt or a Stop of the turn; a submodule or a nested clone never counts - and finds the files whose content differs from each start, committed or not; a tree entered after the start counts as unchanged only while it is clean and on a commit a worktree or a branch (local or remote) pointed at when the turn started. A tree gone at a Stop (a removed worktree) is judged at every Stop of the turn by the commit it left: the tip of the branch it had when last seen, else - its branch gone - its last seen commit while a branch or tag still holds it; unless that commit existed when the turn started or is in the project's HEAD, the tests run on it in a temporary worktree, in a new `0700` folder, made and read by git with no hook of the repository and no fsmonitor (`inCopy()`; filters still run), and removed afterwards with that folder; a commit that cannot be found or checked out is did not run. Nothing changed or only documentation (`.md .markdown .rst .adoc`) -> allow with one line. Otherwise, for each tree that changed, in turn, it picks the command at the project's place in that tree - with the project folder's `.greenwashing.json` of the start of the turn for every tree (a worktree's own is ignored, and the message says so when it differs) - (`testCommand`, else `npm test` for a real `scripts.test` in `package.json` - next to Python tests (`test_*.py`, `*_test.py`) or pytest settings the project must set `testCommand` - else `python3 -m pytest` when pytest is configured, else `python3 -m unittest discover` when there are Python tests, else did not run with the how-to (for a project the gate could check when the work started; see `support()` below); outside git with no test command and no prompt recorded -> allow with one line, unless a `.git` file or a `.git` folder with a HEAD at or above it shows a checkout git cannot read; the project's folder missing in a tree -> did not run), runs it with `CI=true` in its own process group, stopped with the hook, at the timeout (`timeoutSeconds`, default 600, at most 3600; the project's value also bounds all runs of one Stop together) or past 64 MB of output, stops at the first run that is not green, reads the counts of pytest, unittest, jest, vitest and `node --test`, and decides: passed -> allow with one line (command and counts); failed or did not run (no counts, zero tests ran, a file that could not run, a non-zero exit with no failed test, not found, timeout, a broken config, the gate itself failing) -> block with the command, counts, reason, last 20 lines and GW-50 (did not run) or GW-08 (zero tests); after 3 blocks in a row -> allow with a red "WORK NOT ACCEPTED" line. The count restarts on a new prompt and when `stop_hook_active` is false. A block for a run lists up to 10 failed test names from the output before the last 20 lines. Before the tests, quick checks read the test lines the turn added or changed, in each tree against its start (the prompt also keeps the text of each dirty test file, up to 1 MiB, and the hash of the project's `.greenwashing.json` also when git ignores it), in a removed worktree's commit against that tree's start, and in a tree entered later against the newest commit on its first-parent line that existed when the turn started; a new test file that keeps, in order, at least half of its lines from a test file the turn deleted is read against that file (a move): a `.greenwashing.json` changed since the start of this turn blocks (GW-114), also with nothing else changed; then, in test files (`testFileKind()`: what jest 30, vitest 5 and `node --test` collect by default, `test*.py` (unittest discover), `*_test.py`), a new skip, focus or expected-failure marker (GW-17; a new test in a suite that never runs, or whose skip condition reads `CI`, counts too), a new or changed test with no assertion (GW-18), a check whose two sides are the same (GW-01), each switchable in `.greenwashing.json` `checks`; JS/TS by the scanner in `checks.js`, Python by `python_checks.py` under `<python> -I` (`"python"` in the settings, else `python3`; ast; no such Python or an unreadable file -> did not run, with how to set `"python"`). A finding blocks like a failed test (same count), with file, line and entry; changed lines that cannot be told -> did not run; outside git, or with no start of the turn recorded, the tests run, the checks do not, and the allow line says so. Removed tests (with the skip check, GW-17): the quick checks list the tests of every changed test file at the start (`jsTests()`, `list_tests()` in `python_checks.py`; a file the user changed after a Stop that let the agent stop as WORK NOT ACCEPTED as it was at the next prompt, `ended` -> `adopted`) and now (a test file moved with half its lines kept under its old name, `movedFrom()`), and `removedTests()` keeps a test whose key (its name, quotes in one form; `list_tests()`: only the definition Python keeps) is still in its file, or whose body a new test has, one new test for one removed, in its file or in one the project's runners still collect (`carries()`, `collectedBy()`: the files each runner collects by default, seen in live runs; `node --test` by the Node the gate runs on); the rest block with file, name and GW-17, unless the user's prompt of this turn has the words "allow test removal" (`PERMISSION`, `allowRemoval`: at the first Stop after the prompt and its continuations after a block; cleared when a Stop accepts the turn, and a later Stop with `stop_hook_active` false - a turn with no prompt, `turnStopped` - clears it and `ended`), and then the accepted line lists them, and the test files as that Stop saw them are the measure until the next prompt (`adopted`); the prompt after a turn with the words that was not accepted takes the test files it changed as they are then. Moves are judged from the project's folder in the tree (`quickChecks()` `place`), and a Python class a runner collects also lists the tests it inherits from classes of its file. Whether the gate can check the project (`support()`: a `testCommand` a human set, or a found command that runs pytest, unittest, jest, vitest or `node --test`, with the runners it names) is decided at the session's first prompt, again when a human changed `.greenwashing.json` between turns, and for a project not checked after each turn the gate let end; once checked it stays checked for the session. A project it cannot check ends each turn with a "NOT checked" line (`notChecked()`; one that had no test command at the start and has one it checks at the Stop is told the command the next turn is checked with), unless a `.greenwashing.json` changed during the turn (GW-114, outside git too, where the prompt after any turn keeps a file still as the last Stop saw it as the agent's: `seenSettings`) or git cannot read the checkout. `node plugin/gate/hook.js session` (SessionStart) and every event check the Node version first: older than `MIN_NODE` (20) -> the prompt prints nothing, the session and each Stop print a `systemMessage` that the gate is off (`gateOff()`), and nothing blocks. Then the state folder (`stateFolder()`): one that cannot be made or is not safe (a link, not a folder, another user's, open to others) turns the gate off the same way (`stateOff()`, with the folder and what is wrong; the prompt says it on stderr only), and nothing is kept there. No model calls, no dependencies: Node 20+ standard library; logic in `plugin/gate/lib/` apart from the hook I/O in `hook.js` and the shared test run in `runner.js`.

The mutation command (`node plugin/gate/mutate.js`, the plugin command `/greenwashing:mutants`; run by hand, never on Stop): the JS/TS and Python code lines (`codeKind()`: not tests, test folders or runner config) added since the merge base of HEAD with `--base` or the main branch (`origin/HEAD`, `origin/main`, `origin/master`, `main`, `master`), committed or not, untracked files too, under the project's folder; the breaks (`mutants.js` with the checks' scanner, `python_mutants.py` with ast: comparison flipped, `if` negated, guard removed, order removed - `.sort(...)`, `.toSorted(...)`, `.reverse()`, `.toReversed()` taken away, `sorted(x, ...)` to `list(x)`, `reversed(x)` to `x`, `x.sort(...)`/`x.reverse()` on its own to `pass` -, return value to `null`/`None`, `true`/`false` swapped, number + 1), at most `limit` of them in a fixed order that gives every file, and every kind in a file (in the order of `OPERATORS`), a turn before any gets a second (`choose()`), tried in that order and reported in the order of place (`byPlace`); Python's breaks are tried only when of a known kind on a changed line (`touches()`); a temporary copy of the working tree in a new `0700` folder (the files git lists; `.venv`, `venv`, submodules and nested repositories linked; `node_modules` a folder of its own with each entry linked, the caches `.cache`, `.vite`, `.vitest` not, and a workspace package's link pointing into the copy; never made or written through a link, `plainPath()` and `writeInCopy()`: a file the tests made a link, put behind one, gave a second name (a hard link) or removed is not broken, and its run did not start; a run during which that happens did not run, `refused`) removed in every outcome (a folder the tests left read-only made writable first) and on SIGTERM/SIGINT/SIGHUP/SIGQUIT; the gate's test command, chosen in the project folder, run with `CI=true` and `PYTHONDONTWRITEBYTECODE=1`; a control run on the unchanged copy, with all the time left, must pass; its length gives an estimate (`estimate()`: the control run's length times the control breaks and breaks to go, what fits in the time for everything, and the options to change for all of them - a `--timeout` with the runs half again as long and one of them all its time, a `--run-timeout` when a human's is shorter than the control run, whose breaks then do not run; a control run that is not green runs none), printed at once and repeated in the report, and the time of each run with a break (without a `--run-timeout` the control run's x 1.5 + 10 s); then a control break per file with a break chosen (`controlBreak()`: a function that throws, called at once, after a BOM and a `#!` line; Python: a `raise` before the line `python_mutants.py` gives, after the docstring and the `__future__` imports), whose green run marks the file's breaks "not exercised" (did not run; the tests do not run that file: an editable install, a built copy, another path, no test) and whose timeout marks them did not run; then each break of the other files alone, its file restored after; the gate's verdict gives killed (failed), survived (passed) or did not run (never caught, GW-61); exit 0 all killed, 1 a survivor, 2 something did not run or nothing to try; limits `limit` 20, `timeoutSeconds` 600 for everything, `runTimeoutSeconds` none (from the control run; each at most 86400), from `"mutants"` in `.greenwashing.json` or the options; survivors get a hint citing GW-02, GW-04 or GW-11; the report says the time taken before its result.

Tests: `tests/gate/*.test.js` (`node --test`) - `mutants.test.js` (the breaks, their selection, the estimate and the report; every break of this repository's own JS still compiles) and `mutate.test.js` (the command on real temporary projects: outcomes, did not run, the order breaks, the order the breaks are tried in when the time runs out, the estimate printed at once and the options it proposes, the control breaks - a built copy, an editable install's `.pth`, a control that does not finish - the user's files byte for byte, links, signals, limits, the changed lines); the parser on real output of pytest 9.1.1, unittest (Python 3.11, 3.12), jest 30.5.2, vitest 5.0.1 and `node --test` (Node 20, 22); verdicts, decisions, change detection, command choice, failed test names; the quick checks (`checks.test.js`, JS/TS and Python one by one, with honest cases) and the line diff (`diff.test.js`, against a longest common subsequence); `hook.test.js` runs `hook.js` with hook JSON on stdin in real temporary git projects (turn boundaries, worktrees, nested repositories, signals, state, removed tests and the words that allow them, projects the gate cannot check, a Node claiming to be 18 through `--require`); `plugin.test.js` checks the plugin folder and the hook configs (below). Run on Node 20, 22, 24 (CI).

Depends on: Node 20+ (`MIN_NODE`, the oldest Node CI tests) and git on PATH; `python3` on PATH (or `"python"`) for Python test files, the tests they list and Python breaks (missing -> did not run); `CATALOG.md` (GW-01, GW-08, GW-17, GW-18, GW-50 and GW-114, cited by URL; the mutation command's GW-02, GW-04, GW-11 and GW-61); the Claude Code hook contract (hooks reference: Stop input `stop_hook_active`, `decision: "block"` + `reason`, `systemMessage` shown to the user and not the agent (also on SessionStart, live), per-hook `timeout`, UserPromptSubmit default timeout 30 s and its input `prompt`, input `cwd` that follows the agent and `CLAUDE_PROJECT_DIR` that stays on the project, a command hook that cannot start is a non-blocking error); the project's `.greenwashing.json`.

Breaks: `tests/gate/` (messages and decisions are its contract); the plugin's `plugin/hooks/hooks.json` and this repository's `.claude/settings.json` (they call `${CLAUDE_PLUGIN_ROOT}/gate/hook.js` and `$CLAUDE_PROJECT_DIR/plugin/gate/hook.js` `session|prompt|stop`, and the session hook's shell prints `gateOff(NO_NODE)`); `.github/workflows/ci.yml` (`MIN_NODE` is its oldest Node, `plugin.test.js`); `plugin/commands/mutants.md` (calls `${CLAUDE_PLUGIN_ROOT}/gate/mutate.js`); CI "Gate tests" step; `docs/limitations.md` (states what the gate and the mutation command do not catch); `bench/` (runs `plugin/gate/hook.js`, `plugin/gate/mutate.js` and the command choice: any change of what they decide changes `bench/RESULTS.md`, and CI "Bench numbers" goes red until it is regenerated); `README.md` (its scene and table show the gate's replies on four bench cases, and `bench/readme` takes `MIN_NODE` for its "Node 20+": a changed message turns CI "README check" red until the README shows it); `docs/configuration.md` (the settings and the mutation check's options, with their defaults, written by hand); `SECURITY.md` (written by hand: what the hooks and the command run - their own scripts, git and the test command - and that what they keep on disk is the user's alone; the known limits are those `docs/limitations.md` lists); `PRIVACY.md` (written by hand, each of its facts the code's: the agent gets the gate's reply only when it stops a turn (`decision: "block"` + `reason`), and that reply can quote the last lines of the test output (`blockReason()`, `TAIL_LINES`); a state file per session and project in the gate's own folder of the temp folder, open to the user alone (`0700`, `0600`) or not kept at all (`stateFolder()`, `stateOff()`, `saveState()`), holding what `NO_STATE`'s fields, `snapshot()`, `sighting()` and `support()` (its `why` can quote `scripts.test`) record - every field listed in the note - which the gate never deletes; temporary copies, removed when done: the gate's checkout of a removed worktree's commit (`runAtCommit()`) and the mutation check's copy (`makeCopy()`, `removeCopy()`); the test command run with `CI=true` by both (`runTests()`) and with `PYTHONDONTWRITEBYTECODE=1` by the mutation check (`RUN_ENV`); the mutation check's runs on code it broke (`runBroken`); no network, AI model or telemetry of its own: only git's, which may fetch the objects a partial clone lacks).

Traps:
- touching `MAX_TIMEOUT_SECONDS` or a Stop hook `timeout` - keep the hook's timeout 60 s above the longest test run in both `plugin/hooks/hooks.json` and `.claude/settings.json` (`tests/gate/plugin.test.js`), otherwise Claude Code cancels the hook and the agent stops ungated.
- touching the prompt hook - it must never exit 2 (on UserPromptSubmit that erases the user's prompt) or print to stdout (that goes to the agent as context).
- a gate that cannot start (no `node` on PATH, a moved `hook.js`) is a non-blocking hook error in Claude Code: the agent stops ungated; the session hook's `|| echo` tells the user once per session, and each turn still shows Claude Code's own hook errors (live).
- touching `MIN_NODE` or the Node check in `main()` - keep it the oldest Node of the CI matrix and first in `main()`, never blocking and silent on the prompt: on Node 14 and 16 the gate blocked every turn (live), and the prompt's stdout reaches the agent.
- `node --test` counts a test file with no tests as one passing test (live on Node 20 and 22), and a test that prints a summary-like line adds counts: the counts cannot tell these apart.
- touching `RUNNER_FILES` in `checks.js` - CI checks only `node --test` against a live run (`checks.test.js`); jest, vitest, pytest and unittest were probed by hand, so rerun those probes, otherwise a move the runner does not collect counts as kept.
- the gate runs its code from the working tree: an agent that edits `plugin/gate/` during the turn changes what runs; a `.greenwashing.json` edited in the turn blocks (GW-114) and is used only from the next prompt; Safety net guards `.greenwashing.json` only at PR level.
- in this repository `CATALOG.md` and `SKILL.md` are tested data, but by extension they are documentation: a turn that changes only them skips the tests.
- running `node --test` inside a `node --test` child: `NODE_TEST_CONTEXT` makes the nested run refuse ("called recursively"); `hook.test.js` drops it from the hook's environment.
- touching which trees a Stop checks (`places()`, `entered()`) - always the project's tree plus every worktree of the same repository (same `git rev-parse --git-common-dir`) the agent was in during the turn: checking only the `cwd`'s tree let an agent that broke the project end the turn in a clean worktree, and following `cwd` into a nested clone or submodule tested that repository instead.
- touching `runAll()` - the runs of one Stop share the project's timeout; separate timeouts can add up past the Stop hook's own timeout, and Claude Code then lets the agent stop ungated.
- touching `runAtCommit()` - remove the temporary worktree in every outcome, also when a signal stops the hook (the `checkouts` map and the one `onSignal` handler of a Stop), and only with `git worktree remove --force` on its own folder: `git worktree prune` also drops the user's worktrees whose folder is away, with their index. Keep it in its own new `0700` folder and pass `inCopy()` to every git call on it (add, remove, the `ls-files` of `hasPythonTests()`): made by git in the temp folder it is open to every user, and the repository's hooks and fsmonitor run there.

### scripts/leak-check

Purpose: stop leaks before they are published. Three parts, each ends as passed, failed or did not run: (1) gitleaks over the commits in range; (2) references to other repositories of the owner (`brshvdk/<name>`, any case, URLs included), except this repository and the names in `.github/public-repos.txt` read from the base of the range (`BASE_SHA`, else the merge base with `origin/main`; with `--all-history` `origin/main`, else `HEAD`; no base -> part 2 did not run); (3) stop-word patterns from `LEAK_PATTERNS` (one regex per line, pattern #N = line N). Parts 2 and 3 scan tracked files (path and content), every commit in range (author and committer name and email, message, patch) and the PR title and body; a file or patch that is not UTF-8 makes them did not run, image files (`.png .jpg .jpeg .gif .webp .ico` whose bytes start with that format's signature) are not read and are counted as "skipped N image files"; a file with an image name that is not an image is scanned as text and makes all three parts did not run. A commit identity or message, or a file name, that is not UTF-8 also gives did not run. gitleaks ignores exclusions from the scanned repository. Run isolated (`python3 -I`, also in the shebang). Range: `BASE_SHA..HEAD_SHA`, else from the merge base with `origin/main`, else every commit reachable from HEAD; `--all-history` scans every ref. Exit 0 all passed, 1 any failed, 2 nothing failed but something did not run. Output: location and pattern number only.

Inputs: env `LEAK_PATTERNS`, `BASE_SHA`, `HEAD_SHA`, `PR_TITLE`, `PR_BODY`, `GITHUB_EVENT_NAME`; file `.github/public-repos.txt` at the base commit; `git` and `gitleaks` on PATH.

Tests: `tests/test_leak_check.py` - temporary git repositories, made-up patterns, a hostile non-UTF-8 locale, a gitleaks stub.

Depends on: git; gitleaks 8.28.0 (optional: missing -> did not run); `.github/public-repos.txt`.

Breaks: CI "Leak check" step; `tests/test_leak_check.py` (output lines and exit codes are its contract); `tests/test_english_only.py` (loads the script for its image rule, `is_image()` and `is_real_image()`). Guarded by: safety net workflow (changes to it are red there).

Traps:
- touching any text decoding - keep UTF-8 explicit (env, files, git output, stdout), otherwise Cyrillic patterns silently match nothing.
- touching the Cyrillic data of `tests/test_leak_check.py` - keep it `\u` escapes that are Cyrillic at run time, and `CYRILLIC_OTHER` as many UTF-8 bytes as `CYRILLIC_WORD`: Cyrillic text turns `tests/test_english_only.py` red, and other data no longer tests the UTF-8 decoding.
- touching output - never print matched text, a pattern, a matching file name or gitleaks' own log, otherwise public CI logs leak them.
- writing the owner's name, a slash and a repository name anywhere (tests and docs included) - build it at runtime or use a placeholder like `<name>`, otherwise the repository's own leak check goes red.
- touching the gitleaks call - gitleaks 8.28.0 on a bad revision logs an ERR line and "0 commits scanned" and exits 0; keep the checks (no ERR/FTL line, 0 < scanned <= non-merge commits in range), otherwise "not scanned" reads as "clean".
- a PR whose commits add no content (only deletions, renames, mode changes) - gitleaks 8.28.0 counts 0 commits, so the gitleaks part is "did not run" by design.
- running in a shallow clone - the leak check reports "did not run": the history it must scan is incomplete.
- touching the patch scan - keep `--text`, otherwise content git treats as binary (a NUL byte, `.gitattributes`) is never scanned.
- touching the gitleaks call - keep the target the git directory, `--ignore-gitleaks-allow`, `--gitleaks-ignore-path` on an empty directory and no `GITLEAKS_CONFIG*` in its env, otherwise `.gitleaks.toml`, `.gitleaksignore` or `gitleaks:allow` in a PR silence a finding (live-proven with gitleaks 8.28.0).

- adding a file that is neither UTF-8 nor an image (cp1251 text, an archive, a PDF) - parts 2 and 3 report did not run by design; an image needs both the extension and the file signature.
- running the script without `-I` - a module a PR adds next to it (`scripts/argparse.py`) replaces the standard library and can fake a pass.

- adding a file that guards the checks - add a rule to the list in `scripts/safety-net` (the only copy) and a test for that rule in `tests/test_safety_net.py`, otherwise it is unguarded.
- changing the safety net in a PR - the PR itself is still checked by main's version; the change acts only after merge.
- running the script without `-I` - a module merged next to it (`scripts/json.py`) replaces the standard library and prints a fake pass for every later PR.
- touching the comparison - keep it case-insensitive, otherwise a `claude.md` (read as `CLAUDE.md` on the case-insensitive macOS default file system) slips through.
- `tests/` and `scripts/` are not guarded as a whole (owner decision: otherwise every PR with new tests is red and red stops meaning anything) - a new test module can still disable assertions; the project's own gate closes this later.

### .github/workflows/ci.yml

Purpose: the gate for every PR. On `pull_request` (opened, synchronize, reopened, edited), one run per PR at a time (`concurrency` grouped by the PR number, a manual run by its run id; a new run cancels the old one), each job with a `timeout-minutes` of a few times its usual length: job `checks` - `ruff check --no-respect-gitignore .`, `python3 -I -m unittest discover -s tests -v` (red on zero tests or no "Ran N tests" line), the benchmark's tests on the runner's own Node (red on zero tests or no "# tests N" line); job `node`, a matrix of Node 20.20.2, 22.23.3 and 24.21.0 installed from nodejs.org and checked against the SHA-256 pinned in the workflow, then "Check the Node version", the gate's tests `node --test --test-reporter=tap tests/gate/*.test.js`, version printed (same guard), and "Bench numbers": `node bench/run --out "$RUNNER_TEMP/bench"`, red when its RESULTS.md has no summary line, its results.json no cases, or either differs from the committed `bench/RESULTS.md` or `bench/results.json` outside the header (`- Commit:`, `- Date:`, `- Node:`, `- Python:`; the `commit`, `date`, `node`, `python` keys); then "README check": `node bench/readme "$RUNNER_TEMP/bench"`, the README against that same run; job `leak-check` - gitleaks install (official release, pinned version and SHA-256), `python3 -I scripts/leak-check` on the PR range. On `workflow_dispatch`: the same with `--all-history`.

Tests: `tests/test_ci_steps.py` - runs the tools venv, Lint, Unit tests, Gate tests, Bench tests, Bench numbers, README check (with a stand-in for `bench/readme`), Install Node (with a stand-in for curl) and Check the Node version `run:` blocks (and the safety-net step) as written, under `bash -e`, in throwaway directories; rejects step keys other than name, env, run; reads the Node matrix, the job timeouts and the concurrency group from the workflow's text.

Depends on: `scripts/leak-check`; `tests/`; `tests/gate/`; Node release tarballs on nodejs.org (versions and SHA-256 pinned); the runner's own Node, 20 or newer, in the `checks` job (Bench tests run the gate, which refuses an older Node); `bench/` (its tests, `bench/run`, `bench/readme`, the committed `bench/RESULTS.md`); `README.md` (the README check); `ruff.toml` (ruff 0.15.8); repository secret `LEAK_PATTERNS`; `actions/checkout` pinned by commit.

Breaks: acceptance of every PR (the owner merges on green); `tests/test_ci_steps.py` (finds the steps by name).

Traps:
- touching the leak check step - PR title, body and SHAs only through `env:`, never `${{ }}` inside `run:`, otherwise command injection.
- no `LEAK_PATTERNS` secret (also every PR from a fork) - the pattern scan did not run, the step is red.
- touching checkout - keep `fetch-depth: 0`, otherwise the PR range is missing and the leak check did not run.
- touching the Lint step - keep `--no-respect-gitignore`, otherwise a `.gitignore` or `.ignore` added in any folder hides files from ruff.
- touching the Unit tests step - keep `-I` and the "Ran N tests" check, otherwise a root package named like the standard library (`unittest/`) prints a fake OK, or a run of zero tests passes.
- piping a command in a step - GitHub runs steps without a `shell:` key as `bash -e` without pipefail, so `cmd | tee` takes the exit status of `tee` and a failing run goes green.
- touching the Gate tests step - keep the zero and no-count guard: Node 22 reads a glob that matches nothing as "# tests 0" and exits 0.
- touching the Node matrix - pin each version's SHA-256 from its release's SHASUMS256.txt, keep "Check the Node version" before the tests (a `GITHUB_PATH` that did not take effect runs the runner's own Node) and keep its oldest version equal to `MIN_NODE` (`plugin.test.js`).
- touching `concurrency` - keep the PR number with the run id as the fallback: a fixed group lets another PR or a manual run cancel runs.
- touching the Bench numbers step - keep the summary and cases checks before the comparison (two files of header lines only compare equal) and compare both `RESULTS.md` and `results.json`; the header pattern must drop only the four header lines of each, or a changed number passes.
- touching the tools venv step - keep `python3 -I -m venv` run outside the checkout, otherwise a `venv.py` in the PR builds the environment whose `bin/` (fake `ruff`, `python3`) comes first on PATH for Lint and Unit tests.
- `-I` does not cover `tests/` itself: `unittest discover` puts `tests/` first on `sys.path`, so a `tests/json.py` still replaces `json` (the same open risk as an unguarded test module).
- a `# ruff: noqa` or `# flake8: noqa` comment, or a `# ruff: disable[...]` range, still hides code from ruff (open, owner decision; `--ignore-noqa` closes all three - checked by a run).
- moving the leak check into a job that runs PR tests or tools first - that code can rewrite `GITHUB_ENV` / `GITHUB_PATH` of later steps and fake the leak check; keep it in its own job.
