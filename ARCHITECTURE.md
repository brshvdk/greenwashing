# ARCHITECTURE

Map of the repository: only what exists now. All three product modules are here: the catalog, the skill and the gate (with its mutation command), the last two shipped as a Claude Code plugin; the benchmark measures the gate.

## Modules

### CATALOG.md

Purpose: the public catalog - the ways a test suite goes green without the code being right. Data, not code. Sections `## A.` to `## H.`; each entry is a `### GW-NN Title` heading followed by exactly three list items in order: `- **Looks like:**`, `- **Why it's green:**`, `- **Catch it:**`. IDs are stable and never renumbered; gaps between sections are on purpose. The catalog is the only source of its entries: nothing else counts them or lists their numbers.

Tests: `tests/test_catalog.py` - the structure only, read line by line as Markdown splits lines: entry headings (ASCII number in one form, a title with an ASCII letter or digit), numbers unique and ascending, the three lines in order and each with an ASCII letter or digit, sections A-H in order and none empty, no entry outside them, and outside entries no line that starts like markup able to hide entries or move them under another heading (indented or quoted lines, HTML, code fences, headings other than a `# ` title on the first line, setext underlines); markup after a list marker or in the middle of a line is not checked. Mutants of the real catalog must report exactly the rules they break, valid variants none.

Depends on: nothing.

Breaks: `tests/test_catalog.py` (the structure is its contract); `tests/test_skill.py` (the skill cites entry numbers); the gate's block messages (cite GW-01, GW-08, GW-17, GW-18, GW-50 and GW-114; `gate/test/verdict.test.js` checks each is an entry); the mutation command's report (GW-02, GW-04, GW-11 and GW-61; `gate/test/mutants.test.js` checks the hints' entries); `bench/cases` (each case names an entry; `bench/run` refuses a number that is no heading); the link in `README.md` and the link in `skills/greenwashing/SKILL.md`.

Traps:
- adding a section after H or changing the three lines - change `SECTIONS` or `FIELDS` in `tests/test_catalog.py` in the same PR, otherwise the test goes red.
- renumbering an entry - the test checks that numbers are unique and ascending, not that they stay the same, so a renumbering passes it.
- inline HTML or an empty link inside an entry line or title - the test only asks for one ASCII letter or digit, so `&nbsp;`, `<!-- x -->` or `[](url)` passes and renders empty.
- writing outside entries - the markup rule is conservative: an autolink, inline HTML or `#1` at the start of a line, an indented or nested list, a GitHub alert (`> [!NOTE]`) and `---` turn the test red.
- touching line splitting in the test - keep CRLF, CR and LF only, otherwise (`str.splitlines`) U+2028, form feed and others split an entry that Markdown renders as one line.

### skills/greenwashing/SKILL.md

Purpose: the skill for coding agents that read the Agent Skills format: what to do before reporting "done" and how to report, citing catalog entries by `GW-NN`. Frontmatter `name` (the folder name) and `description`. Meant to be installed with `npx skills add brshvdk/greenwashing`: the `skills` CLI looks for `skills/<name>/SKILL.md` (its npm README, 1.7.0), and a live `skills@1.7.0` install from a local copy put the file unchanged into the project's `.claude/skills/greenwashing/SKILL.md`. The field rules follow agentskills.io/specification.

Tests: `tests/test_skill.py` - frontmatter present (LF, CRLF or CR endings, a BOM allowed; one-line values, quotes removed, `~`/`null` read as empty; a block value `>` or `|` is reported, the checker cannot measure it); `name` equals the folder, only lower case letters, digits and hyphens, a hyphen only between letters or digits (none at the start or end, never two in a row), at most 64 characters; `description` not empty, at most 1024 characters; the skill cites at least one `GW-NN` and every one is an entry heading of `CATALOG.md`; the catalog's entry count does not appear in the skill. Mutants of the real skill must report exactly the rules they break.

Depends on: `CATALOG.md` (entry numbers, entry count).

Breaks: `tests/test_skill.py` (the frontmatter and cited numbers are its contract); the plugin (loads it from `skills/greenwashing/`, see below).

Traps:
- removing or renumbering a catalog entry the skill cites - `tests/test_skill.py` goes red; change the skill in the same PR.
- adding or removing a catalog entry - the forbidden number changes, so any bare number in the skill equal to the new count (`0.87`, `line 87`) turns `tests/test_skill.py` red.
- adding an entry numbered GW-19, GW-99 or GW-199 - `tests/test_skill.py` uses these as numbers missing from the catalog (`test_id_not_in_catalog`); pick another gap in the same PR.
- the skill links to `CATALOG.md` on `main` by URL - renaming or moving the catalog breaks the link, and no test checks it.

### gate (`gate/`)

Purpose: the Claude Code hooks that keep an agent from finishing a turn that changed code while the tests fail or did not really run. `node gate/hook.js prompt` (UserPromptSubmit) records the start of the turn - HEAD and a content hash of every file git reports as dirty - in the project's git tree and, when the agent is in another worktree of the same repository, in that one too, plus the commits the worktrees and branches of the repository point at; the state file sits in a per-user `0700` folder of the temp directory (one per session and project). The start moves only when a Stop accepts the work (green tests, or no code changed): after an interrupted turn, a blocked one or one let go as "WORK NOT ACCEPTED", the next prompt keeps the starts, so the work the gate did not accept is measured again. Every prompt also records the gate's settings as they are then: the project's `.greenwashing.json` text, and the `.greenwashing.json` files of each tree (a snapshot of those files only), against which GW-114 is measured, so a human's edit between turns never blocks; every prompt and Stop records those files as the gate sees them (`stopped`), and at a prompt after a turn no Stop accepted, each file that differs from the turn before's snapshot but is still as the gate last saw it keeps its earlier state, in a tree that has such a snapshot, and the project's text with it (the agent's change carried over keeps blocking; a file changed since is the user's). `node gate/hook.js stop` (Stop) checks every tree the turn has seen - the project's, and every worktree of the repository that was the input's `cwd` at a prompt or a Stop of the turn; a submodule or a nested clone never counts - and finds the files whose content differs from each start, committed or not; a tree entered after the start counts as unchanged only while it is clean and on a commit a worktree or a branch (local or remote) pointed at when the turn started. A tree gone at a Stop (a removed worktree) is judged at every Stop of the turn by the commit it left: the tip of the branch it had when last seen, else - its branch gone - its last seen commit while a branch or tag still holds it; unless that commit existed when the turn started or is in the project's HEAD, the tests run on it in a temporary worktree that is removed afterwards; a commit that cannot be found or checked out is did not run. Nothing changed or only documentation (`.md .markdown .rst .adoc`) -> allow with one line. Otherwise, for each tree that changed, in turn, it picks the command at the project's place in that tree - with the project folder's `.greenwashing.json` of the start of the turn for every tree (a worktree's own is ignored, and the message says so when it differs) - (`testCommand`, else `npm test` for a real `scripts.test` in `package.json` - next to Python tests (`test_*.py`, `*_test.py`) or pytest settings the project must set `testCommand` - else `python3 -m pytest` when pytest is configured, else `python3 -m unittest discover` when there are Python tests, else did not run with the how-to (for a project the gate could check when the work started; see `support()` below); outside git with no test command and no prompt recorded -> allow with one line, unless a `.git` file or a `.git` folder with a HEAD at or above it shows a checkout git cannot read; the project's folder missing in a tree -> did not run), runs it with `CI=true` in its own process group, stopped with the hook, at the timeout (`timeoutSeconds`, default 600, at most 3600; the project's value also bounds all runs of one Stop together) or past 64 MB of output, stops at the first run that is not green, reads the counts of pytest, unittest, jest, vitest and `node --test`, and decides: passed -> allow with one line (command and counts); failed or did not run (no counts, zero tests ran, a file that could not run, a non-zero exit with no failed test, not found, timeout, a broken config, the gate itself failing) -> block with the command, counts, reason, last 20 lines and GW-50 (did not run) or GW-08 (zero tests); after 3 blocks in a row -> allow with a red "WORK NOT ACCEPTED" line. The count restarts on a new prompt and when `stop_hook_active` is false. A block for a run lists up to 10 failed test names from the output before the last 20 lines. Before the tests, quick checks read the test lines the turn added or changed, in each tree against its start (the prompt also keeps the text of each dirty test file, up to 1 MiB, and the hash of the project's `.greenwashing.json` also when git ignores it), in a removed worktree's commit against that tree's start, and in a tree entered later against the newest commit on its first-parent line that existed when the turn started; a new test file that keeps, in order, at least half of its lines from a test file the turn deleted is read against that file (a move): a `.greenwashing.json` changed since the start of this turn blocks (GW-114), also with nothing else changed; then, in test files (`testFileKind()`: what jest 30, vitest 5 and `node --test` collect by default, `test*.py` (unittest discover), `*_test.py`), a new skip, focus or expected-failure marker (GW-17; a new test in a suite that never runs, or whose skip condition reads `CI`, counts too), a new or changed test with no assertion (GW-18), a check whose two sides are the same (GW-01), each switchable in `.greenwashing.json` `checks`; JS/TS by the scanner in `checks.js`, Python by `python_checks.py` under `<python> -I` (`"python"` in the settings, else `python3`; ast; no such Python or an unreadable file -> did not run, with how to set `"python"`). A finding blocks like a failed test (same count), with file, line and entry; changed lines that cannot be told -> did not run; outside git, or with no start of the turn recorded, the tests run, the checks do not, and the allow line says so. Removed tests (with the skip check, GW-17): the quick checks list the tests of every changed test file at the start (`jsTests()`, `list_tests()` in `python_checks.py`; a file the user changed after a Stop that let the agent stop as WORK NOT ACCEPTED as it was at the next prompt, `ended` -> `adopted`) and now (a test file moved with half its lines kept under its old name, `movedFrom()`), and `removedTests()` keeps a test whose name is still in its file or whose body is in its file or in one the project's runners still collect (`carries()`, `collectedBy()`: default file names per runner); the rest block with file, name and GW-17, unless the user's prompt of this turn has the words "allow test removal" (`PERMISSION`, `allowRemoval`, cleared when the turn ends), and then the accepted line lists them. Whether the gate can check the project (`support()`: a `testCommand` a human set, or a found command that runs pytest, unittest, jest, vitest or `node --test`, with the runners it names) is decided at the session's first prompt, again when a human changed `.greenwashing.json` between turns, and for a project not checked after each turn the gate let end; once checked it stays checked for the session. A project it cannot check ends each turn with a "NOT checked" line (`notChecked()`), unless a `.greenwashing.json` changed during the turn (GW-114) or git cannot read the checkout. `node gate/hook.js session` (SessionStart) and every event check the Node version first: older than `MIN_NODE` (20) -> the prompt prints nothing, the session and each Stop print a `systemMessage` that the gate is off (`gateOff()`), and nothing blocks. No model calls, no dependencies: Node 20+ standard library; logic in `gate/lib/` apart from the hook I/O in `hook.js` and the shared test run in `runner.js`.

The mutation command (`node gate/mutate.js`, the plugin command `/greenwashing:mutants`; run by hand, never on Stop): the JS/TS and Python code lines (`codeKind()`: not tests, test folders or runner config) added since the merge base of HEAD with `--base` or the main branch (`origin/HEAD`, `origin/main`, `origin/master`, `main`, `master`), committed or not, untracked files too, under the project's folder; the breaks (`mutants.js` with the checks' scanner, `python_mutants.py` with ast: comparison flipped, `if` negated, guard removed, return value to `null`/`None`, `true`/`false` swapped, number + 1), at most `limit` of them in a fixed order that gives every file, and every kind in a file, a turn before any gets a second (`choose()`); Python's breaks are tried only when of a known kind on a changed line (`touches()`); a temporary copy of the working tree (the files git lists; `.venv`, `venv`, submodules and nested repositories linked; `node_modules` a folder of its own with each entry linked, the caches `.cache`, `.vite`, `.vitest` not, and a workspace package's link pointing into the copy) removed in every outcome (a folder the tests left read-only made writable first) and on SIGTERM/SIGINT/SIGHUP/SIGQUIT; the gate's test command, chosen in the project folder, run with `CI=true` and `PYTHONDONTWRITEBYTECODE=1`; a control run on the unchanged copy must pass; then a control break per file with a break chosen (`controlBreak()`: a function that throws, called at once, after a BOM and a `#!` line; Python: a `raise` before the line `python_mutants.py` gives, after the docstring and the `__future__` imports), whose green run marks the file's breaks "not exercised" (did not run; the tests do not run that file: an editable install, a built copy, another path, no test) and whose timeout marks them did not run; then each break of the other files alone, its file restored after; the gate's verdict gives killed (failed), survived (passed) or did not run (never caught, GW-61); exit 0 all killed, 1 a survivor, 2 something did not run or nothing to try; limits `limit` 20, `timeoutSeconds` 600 for everything, `runTimeoutSeconds` 120 (each at most 86400), from `"mutants"` in `.greenwashing.json` or the options; survivors get a hint citing GW-02, GW-04 or GW-11.

Tests: `gate/test/*.test.js` (`node --test`) - `mutants.test.js` (the breaks, their selection and report; every break of this repository's own JS still compiles) and `mutate.test.js` (the command on real temporary projects: outcomes, did not run, the control breaks - a built copy, an editable install's `.pth`, a control that does not finish - the user's files byte for byte, links, signals, limits, the changed lines); the parser on real output of pytest 9.1.1, unittest (Python 3.11, 3.12), jest 30.5.2, vitest 5.0.1 and `node --test` (Node 20, 22); verdicts, decisions, change detection, command choice, failed test names; the quick checks (`checks.test.js`, JS/TS and Python one by one, with honest cases) and the line diff (`diff.test.js`, against a longest common subsequence); `hook.test.js` runs `hook.js` with hook JSON on stdin in real temporary git projects (turn boundaries, worktrees, nested repositories, signals, state, removed tests and the words that allow them, projects the gate cannot check, a Node claiming to be 18 through `--require`); `plugin.test.js` checks the hook configs (below). Run on Node 20, 22, 24 (CI).

Depends on: Node 20+ (`MIN_NODE`, the oldest Node CI tests) and git on PATH; `python3` on PATH (or `"python"`) for Python test files, the tests they list and Python breaks (missing -> did not run); `CATALOG.md` (GW-01, GW-08, GW-17, GW-18, GW-50 and GW-114, cited by URL; the mutation command's GW-02, GW-04, GW-11 and GW-61); the Claude Code hook contract (hooks reference: Stop input `stop_hook_active`, `decision: "block"` + `reason`, `systemMessage` shown to the user and not the agent (also on SessionStart, live), per-hook `timeout`, UserPromptSubmit default timeout 30 s and its input `prompt`, input `cwd` that follows the agent and `CLAUDE_PROJECT_DIR` that stays on the project, a command hook that cannot start is a non-blocking error); the project's `.greenwashing.json`.

Breaks: `gate/test/` (messages and decisions are its contract); the plugin's `hooks/hooks.json` and this repository's `.claude/settings.json` (they call `gate/hook.js session|prompt|stop`, and the session hook's shell prints `gateOff(NO_NODE)`); `.github/workflows/ci.yml` (`MIN_NODE` is its oldest Node, `plugin.test.js`); `commands/mutants.md` (calls `gate/mutate.js`); CI "Gate tests" step; `docs/limitations.md` (states what the gate and the mutation command do not catch); `bench/` (runs `gate/hook.js`, `gate/mutate.js` and the command choice: any change of what they decide changes `bench/RESULTS.md`, and CI "Bench numbers" goes red until it is regenerated).

Traps:
- touching `MAX_TIMEOUT_SECONDS` or a Stop hook `timeout` - keep the hook's timeout 60 s above the longest test run in both `hooks/hooks.json` and `.claude/settings.json` (`gate/test/plugin.test.js`), otherwise Claude Code cancels the hook and the agent stops ungated.
- touching the prompt hook - it must never exit 2 (on UserPromptSubmit that erases the user's prompt) or print to stdout (that goes to the agent as context).
- a gate that cannot start (no `node` on PATH, a moved `hook.js`) is a non-blocking hook error in Claude Code: the agent stops ungated; the session hook's `|| echo` tells the user once per session, and each turn still shows Claude Code's own hook errors (live).
- touching `MIN_NODE` or the Node check in `main()` - keep it the oldest Node of the CI matrix and first in `main()`, never blocking and silent on the prompt: on Node 14 and 16 the gate blocked every turn (live), and the prompt's stdout reaches the agent.
- `node --test` counts a test file with no tests as one passing test (live on Node 20 and 22), and a test that prints a summary-like line adds counts: the counts cannot tell these apart.
- the gate runs its code from the working tree: an agent that edits `gate/` during the turn changes what runs; a `.greenwashing.json` edited in the turn blocks (GW-114) and is used only from the next prompt; Safety net guards `.greenwashing.json` only at PR level.
- in this repository `CATALOG.md` and `SKILL.md` are tested data, but by extension they are documentation: a turn that changes only them skips the tests.
- running `node --test` inside a `node --test` child: `NODE_TEST_CONTEXT` makes the nested run refuse ("called recursively"); `hook.test.js` drops it from the hook's environment.
- touching which trees a Stop checks (`places()`, `entered()`) - always the project's tree plus every worktree of the same repository (same `git rev-parse --git-common-dir`) the agent was in during the turn: checking only the `cwd`'s tree let an agent that broke the project end the turn in a clean worktree, and following `cwd` into a nested clone or submodule tested that repository instead.
- touching `runAll()` - the runs of one Stop share the project's timeout; separate timeouts can add up past the Stop hook's own timeout, and Claude Code then lets the agent stop ungated.
- touching `runAtCommit()` - remove the temporary worktree in every outcome, also when a signal stops the hook (the `checkouts` map and the one `onSignal` handler of a Stop), and only with `git worktree remove --force` on its own folder: `git worktree prune` also drops the user's worktrees whose folder is away, with their index.
- touching the prompt hook's state writes - forget the last turn before the snapshot and keep the start of a turn no Stop accepted (`accepted` is set only by an allow; a release as WORK NOT ACCEPTED leaves it false), otherwise a stop measures from a stale or a too-late start and misses changes, or unaccepted work becomes the start.
- touching GW-114 or the per-turn settings snapshot (`turn`, `settingsIn()`) - measure `.greenwashing.json` from the latest prompt, and count a tree whose settings file changed since then as changed even when nothing else differs from its start: measured from the older start a human's edit between turns blocks; skipped, the agent can put back what the human changed.
- touching the prompt after an unaccepted turn (`stopped`, `carried`) - judge each settings file alone, against what the gate last saw (record it at every prompt and Stop), and carry only in a tree with an earlier snapshot: judged by the whole tree, a user's edit of another package's file made the agent's fake command theirs; against an older Stop, a user's change undone during a cut-off turn blocked; carried without a snapshot, a user's own change in a worktree entered mid-turn blocked every turn after.
- touching `rootFiles()` or the settings passed to `runIn()`/`quickChecks()` - every tree uses the project's settings text recorded at the prompt; reading a tree's own file lets a worktree's `.greenwashing.json` (ignored by git, so never GW-114) set the command and turn the checks off.
- touching `testFileKind()` - keep it to what the runners collect by default (live: jest 30.5.2, vitest 5.0.1, `node --test` on Node 20 and 22; unittest discover's `test*.py`), otherwise a test file goes unchecked or a helper is read as tests.
- touching `snapshot()` - keep the project's `.greenwashing.json` among its `dirty` hashes whatever git says: git does not list an ignored file, and a change to it would go unseen (GW-114).
- touching `onStop()` - run the quick checks only with a start the prompt recorded (a Stop keeps the trees it saw with a null start): without one every line reads as new, and every stop blocks with a false GW-114.
- touching the suite rule of the checks - a test in a suite that never runs counts only when it is new there (its first line added, nothing removed in its place) or a test of its name was outside every such suite in the start text the hook passes (`checkJs(..., before)`, `before` in the Python request), and only for markers without a condition or with one that reads `CI` (`readsCi()`, `reads_ci()`: only the condition, never a skip reason): otherwise every rename in an old skipped suite, and every new test in a module skipped on another platform, blocks, or a suite's bracket moved around a failing test passes. A test in a suite skipped on CI is still read for assertions (it runs elsewhere).
- touching a message that says how to set the test command - say a human sets it between turns: an agent that edits `.greenwashing.json` during the turn is blocked (GW-114).
- touching `sinceKnown()` or `changesIn()` - never diff a folder that is no longer the top of its own checkout: git reads it as the parent repository and the checks see no changed lines.
- touching the checks' line spans - a Python function ends at its last statement, so a removed last line lies just past it (a gap at end + 1 counts); a JS test's span ends at its closing bracket.
- this repository's own hook tests write test files: their fixtures must be honest tests (`NODE_PASS` asserts), otherwise the quick checks block before the tests run.
- touching the test command's environment - `CI=true` keeps a script that checks it out of its watch mode, but an explicit `jest --watchAll` still watches until the timeout, and jest then fails a new snapshot instead of writing it (both live, jest 30.5.2).
- touching `removedTests()`, `jsTests()` or `list_tests()` - a test stays by its name in its file or its body in any changed test file of its tree; a body with the name in it makes every rename a removal, and one without the table, options or skip condition lets a changed table pass as a rename.
- touching `stopped`, `ended` or `adopted` - adopt the user's test file changes only against `ended` (the snapshot of a Stop that let the agent stop), use it once, and let `adopted` add up until a turn is accepted: adopted against the last Stop or prompt, a test the agent removed before an interrupt passes as the user's; not added up, a user's removal blocks again after a turn cut off before its Stop.
- touching `PERMISSION` - read only UserPromptSubmit's `prompt`, at every prompt, for that turn only; the words are `PERMISSION_WORDS` in `verdict.js`, which the block message quotes.
- touching `support()` or where it is decided - keep a checked project checked for the session and decide again only on a human's settings change or, for an unchecked one, after a turn the gate let end (else the agent swaps the test script for a wrapper in an accepted turn, or removes it and is let go as WORK NOT ACCEPTED, and the next turn passes); keep GW-114 in a project the gate does not check (else a `testCommand` the agent writes counts as the user's from the next turn); keep the check of a checkout git cannot read before the NOT-checked line.
- touching `collectedBy()` or `carries()` - a moved test keeps its place only where every runner of the project that collected its old file collects the new one: counted by `testFileKind()` alone, a test moved to `a.spec.js` in a `node --test` project, or to `a_test.py` under unittest, stopped running and passed.
- touching the mutation command's changed lines (`addedLines()`, `ownLines()`, the diff options) - count only the `+` lines of each hunk, map git's lines (split at LF) to the file's (split at CRLF, CR, LF), keep `--text` and `-c diff.autoRefreshIndex=false`: otherwise `diff.interHunkContext` breaks unchanged lines, a lone CR moves the breaks onto old lines, a `-diff` attribute hides a file, and git rewrites the user's index (each seen in a run).
- touching `choose()` - give every file, and every kind in a file, a turn before any gets a second: a plain spread let 200 tested numbers in one file crowd an untested guard in another out, and the result read "every mutant was killed".
- touching the JavaScript breaks - keep them syntax-safe (a comparison only between a name, a number or a bracket and an operand on one line; a guard only alone on its lines; a return value over a template's lines; no method named if): `stillParses()` drops a broken one only for CommonJS, and under `node --test` a file that cannot load counts as a failed test. Checked by parsing every break of installed packages (node's parser for CommonJS and ES modules, TypeScript's for `.ts`).
- touching `linkModules()` - keep `node_modules` a folder of the copy's own: linked whole, vitest wrote its cache into the user's `node_modules` and a workspace package loaded the user's files (its breaks survived).
- touching the mutation command's copy (`makeCopy()`, `removeCopy()`) - break only regular files (never through a link: a write would land in the user's file), link dependency folders instead of copying them, and remove the copy with `fs.rmSync` (it removes links, it does not follow them; `mutate.test.js` checks the user's tree byte for byte, `.git` and `node_modules` included) in every outcome, on signals too.
- touching the mutation command's outcomes - a run that is not green and not failed is did not run, never killed (GW-61): keep `verdict()` as the only judge and `OUTCOMES` as its mapping; restore each broken file before the next break, or a later break is killed by the earlier one.
- touching `controlBreak()` or `control_line()` - keep the control break a statement that parses and runs before the file's own code (after a BOM and `#!`, after `__future__` imports, not unreachable code): a break that fails to compile or lint makes the test command red for another reason, and a file the tests never load reads as run by them, so its breaks survive falsely again.
- touching the mutation command's Python runs - keep `PYTHONDONTWRITEBYTECODE=1` and no `__pycache__` in the copy: a cached `.pyc` of the same size and second as a break runs instead of it, and the break survives falsely.

### bench (`bench/`)

Purpose: the numbers for the README - how many fake changes the gate and its mutation command catch, and how many honest ones they send back. `bench/cases/<id>/`: `case.json` (kind fake or honest, gw, language js or python, twin, one-line description; a fake's claim "caught" or "not caught" as the tool's docs say; `delete`; scenario `worktree`; `prompt`, the user's prompt, else a fixed neutral one - never the description), `before/` (the project) and `after/` (the files the change writes), every file stored as `<name>.txt`. Every fake has an honest twin from the same `before/`: the right version of the same change. `node bench/run` checks the set (a file without the suffix, an empty part, no cases, a twin that does not answer, another `before/`, a number that is no catalog heading, unequal counts -> did not run, exit 2, nothing written), builds each case as a git project in a temporary folder outside the repository (fixed git identity and dates, no user git config), removed after, and measures three columns: tests only (the gate's command choice on the change - the tree it leaves, or for a worktree case a checkout of the branch the removed worktree left - judged by exit code as CI judges it), gate (`gate/hook.js` prompt, the change, Stop, as Claude Code runs them; a worktree case commits the change in a worktree it then removes), gate + mutants (`gate/mutate.js` on the same tree when the gate allows). Red fake = caught, red honest = false alarm, did not run = neither. Writes `RESULTS.md` (header: commit, date, Node, Python; summary; misses; false alarms; did not run; every case) and `results.json`. Only Python `unittest` and `node --test`, no dependencies (the mocha project runs a stand-in for mocha written for it); the same tables on Node 20, 22 and 24 (runs in the PR 8 session; Python 3.10 to 3.13 in PR 7).

Tests: `bench/test/run.test.js` - the real set (twins, counts, the promised kinds of fake, every file with the suffix), broken sets, the gate's and the mutation command's outcomes, the counts and the Markdown, and a run on a tiny set (a skip, a failing test the command catches, a removed worktree) that leaves nothing in the temp folder, and a temp folder inside the repository refused; CI "Bench numbers" reruns the real set.

Depends on: `gate/hook.js`, `gate/mutate.js`, `gate/lib/command.js` and `gate/runner.js` (the command choice and the test run); `CATALOG.md` (entry numbers); node, npm, python3 and git on PATH.

Breaks: CI "Bench numbers" (the committed `RESULTS.md` and `results.json` are its contract); the README numbers (PR 8, taken from `RESULTS.md` only).

Traps:
- storing a case file under its real name - this repository's gate reads new test files and every `.greenwashing.json`, so the fakes' skips, empty tests and settings changes block every turn that touches them; `bench/run` refuses a file without `.txt`.
- a case whose outcome depends on the runner's version - CI's Node and Python differ from a local run, and the comparison goes red (seen: `--test-name-pattern` matching nothing is zero tests on Node 20 and 21 but one passing test per file on Node 22 and 24); run the set on Node 20, 22 and 24 before committing.
- adding a case - every case needs a twin of the other kind from the same `before/`, so an honest case in a project the gate does not check needs a fake twin (claimed "not caught"); a permission the case needs goes in `prompt`, never in the description.
- changing the gate, the mutation command or a case - regenerate with `node bench/run` and commit `RESULTS.md` and `results.json`, or CI "Bench numbers" is red.
- the tests-only column is red in the set only for the removed-worktree fake (every other fake hides its failure from the test command): keep the case in `bench/test/run.test.js` that the test command catches, or a column stuck at green goes unseen.

### plugin (`.claude-plugin/`, `hooks/hooks.json`)

Purpose: this repository is a Claude Code plugin marketplace named `greenwashing` with one plugin, `greenwashing`, whose root is the repository root (`source: "./"`): `hooks/hooks.json` runs the gate through `${CLAUDE_PLUGIN_ROOT}` (SessionStart, UserPromptSubmit, Stop), the default `skills/` scan loads `skills/greenwashing/SKILL.md` (one copy), and the default `commands/` scan loads `commands/mutants.md`, the command `/greenwashing:mutants` that runs `gate/mutate.js` through `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_PROJECT_DIR}` (both substituted in a command's body; Claude Code 2.1.282 lists it among the plugin's skills). Install: `/plugin marketplace add brshvdk/greenwashing`, then `/plugin install greenwashing@greenwashing`. No `version`: users get each new commit (commit-SHA version). This repository runs the same gate through `.claude/settings.json` with `.greenwashing.json` (Python tests with `-I`, then the gate's tests).

Tests: `gate/test/plugin.test.js` - manifests, exactly one `SKILL.md`, both hook configs' commands and the plugin command's line run as written by `sh -c` from a path with a space (the session hook also with no `node` on PATH), Stop timeouts, `MIN_NODE` against the CI matrix, this repository's `.greenwashing.json`; `claude plugin validate` passes with two warnings (no `version`; `CLAUDE.md` at the plugin root is not loaded as context).

Depends on: `gate/hook.js`; `gate/mutate.js`; `skills/greenwashing/SKILL.md`; the Claude Code plugin and marketplace format.

Breaks: every user install.

Traps:
- adding a top-level component folder or file (`commands/`, `agents/`, `monitors/`, `.mcp.json`, `settings.json`) - the whole repository is the plugin, so it ships to every user.
- moving the skill or the gate out of the repository root - a plugin cannot reference files outside its root, and the cache holds only what is inside it.
- working on this repository with the plugin installed runs the gate twice (plugin and `.claude/settings.json`).
- turning the command into a skill - the docs prefer `skills/` for new plugins, but a second `SKILL.md` breaks `plugin.test.js` (one skill) and would be installed by `npx skills add` as a skill for every agent.
- the command's line runs through the agent's Bash tool, whose inline `!` form has a 2-minute timeout (skills docs): keep the command a text the agent runs in the background, not a `!` line.

### scripts/leak-check

Purpose: stop leaks before they are published. Three parts, each ends as passed, failed or did not run: (1) gitleaks over the commits in range; (2) references to other repositories of the owner (`brshvdk/<name>`, any case, URLs included), except this repository and the names in `.github/public-repos.txt` read from the base of the range (`BASE_SHA`, else the merge base with `origin/main`; with `--all-history` `origin/main`, else `HEAD`; no base -> part 2 did not run); (3) stop-word patterns from `LEAK_PATTERNS` (one regex per line, pattern #N = line N). Parts 2 and 3 scan tracked files (path and content), every commit in range (author and committer name and email, message, patch) and the PR title and body; a file or patch that is not UTF-8 makes them did not run, image files (`.png .jpg .jpeg .gif .webp .ico` whose bytes start with that format's signature) are not read and are counted as "skipped N image files"; a file with an image name that is not an image is scanned as text and makes all three parts did not run. A commit identity or message, or a file name, that is not UTF-8 also gives did not run. gitleaks ignores exclusions from the scanned repository. Run isolated (`python3 -I`, also in the shebang). Range: `BASE_SHA..HEAD_SHA`, else from the merge base with `origin/main`, else every commit reachable from HEAD; `--all-history` scans every ref. Exit 0 all passed, 1 any failed, 2 nothing failed but something did not run. Output: location and pattern number only.

Inputs: env `LEAK_PATTERNS`, `BASE_SHA`, `HEAD_SHA`, `PR_TITLE`, `PR_BODY`, `GITHUB_EVENT_NAME`; file `.github/public-repos.txt` at the base commit; `git` and `gitleaks` on PATH.

Tests: `tests/test_leak_check.py` - temporary git repositories, made-up patterns, a hostile non-UTF-8 locale, a gitleaks stub.

Depends on: git; gitleaks 8.28.0 (optional: missing -> did not run); `.github/public-repos.txt`.

Breaks: CI "Leak check" step; `tests/test_leak_check.py` (output lines and exit codes are its contract). Guarded by: safety net workflow (changes to it are red there).

Traps:
- touching any text decoding - keep UTF-8 explicit (env, files, git output, stdout), otherwise Cyrillic patterns silently match nothing.
- touching output - never print matched text, a pattern, a matching file name or gitleaks' own log, otherwise public CI logs leak them.
- writing the owner's name, a slash and a repository name anywhere (tests and docs included) - build it at runtime or use a placeholder like `<name>`, otherwise the repository's own leak check goes red.
- touching the gitleaks call - gitleaks 8.28.0 on a bad revision logs an ERR line and "0 commits scanned" and exits 0; keep the checks (no ERR/FTL line, 0 < scanned <= non-merge commits in range), otherwise "not scanned" reads as "clean".
- a PR whose commits add no content (only deletions, renames, mode changes) - gitleaks 8.28.0 counts 0 commits, so the gitleaks part is "did not run" by design.
- running in a shallow clone - the leak check reports "did not run": the history it must scan is incomplete.
- touching the patch scan - keep `--text`, otherwise content git treats as binary (a NUL byte, `.gitattributes`) is never scanned.
- touching the gitleaks call - keep the target the git directory, `--ignore-gitleaks-allow`, `--gitleaks-ignore-path` on an empty directory and no `GITLEAKS_CONFIG*` in its env, otherwise `.gitleaks.toml`, `.gitleaksignore` or `gitleaks:allow` in a PR silence a finding (live-proven with gitleaks 8.28.0).
- changing `.github/public-repos.txt` - it is read from the base, so the change takes effect only after merge; a PR cannot allow a name for itself.
- adding a file that is neither UTF-8 nor an image (cp1251 text, an archive, a PDF) - parts 2 and 3 report did not run by design; an image needs both the extension and the file signature.
- running the script without `-I` - a module a PR adds next to it (`scripts/argparse.py`) replaces the standard library and can fake a pass.
- `git commit` itself re-encodes a non-UTF-8 message or name as Latin-1, so such text reaches the repository as valid UTF-8 mojibake that the check cannot recognise.

### safety-net workflow (`.github/workflows/safety-net.yml`, `scripts/safety-net`)

Purpose: make any change to the checks themselves visible as a separate red check "Safety net". Runs on `pull_request_target` (opened, synchronize, reopened, edited - so a PR retargeted to main is checked too), so the workflow and script come from main and a PR cannot switch them off. Reads the PR's changed files through the GitHub API (read-only token; PR number only through `env:`), never checks out or runs PR code. Red when a guarded file is added, changed, removed or renamed (old and new names). The guarded list and its one exemption live only in `scripts/safety-net` (categories: exact paths, the workflows directory; in any folder, agent instruction file names, tool config, the gate's `.greenwashing.json` and Python startup hook names, and `.claude/` folders; compared ignoring case). Runs as `python3 -I scripts/safety-net`. Did not run when the file list is empty, has an entry without a name, or is incomplete (count differs from the PR's `changed_files`). Output: guarded names only.

Tests: `tests/test_safety_net.py` - comparison logic directly, the script against a local fake of the GitHub API.

Depends on: `scripts/safety-net` on main; GitHub API; `actions/checkout` pinned by commit.

Breaks: acceptance of any PR that touches a guarded file (red by design; the owner decides).

Traps:
- touching the workflow - never add a checkout of the PR ref or run PR code: `pull_request_target` runs with the base repository's token.
- adding a file that guards the checks - add a rule to the list in `scripts/safety-net` (the only copy) and a test for that rule in `tests/test_safety_net.py`, otherwise it is unguarded.
- changing the safety net in a PR - the PR itself is still checked by main's version; the change acts only after merge.
- running the script without `-I` - a module merged next to it (`scripts/json.py`) replaces the standard library and prints a fake pass for every later PR.
- touching the comparison - keep it case-insensitive, otherwise a `claude.md` (read as `CLAUDE.md` on the case-insensitive macOS default file system) slips through.
- `tests/` and `scripts/` are not guarded as a whole (owner decision: otherwise every PR with new tests is red and red stops meaning anything) - a new test module can still disable assertions; the project's own gate closes this later.

### .github/workflows/ci.yml

Purpose: the gate for every PR. On `pull_request` (opened, synchronize, reopened, edited), one run per PR at a time (`concurrency` grouped by the PR number, a manual run by its run id; a new run cancels the old one), each job with a `timeout-minutes` of a few times its usual length: job `checks` - `ruff check --no-respect-gitignore .`, `python3 -I -m unittest discover -s tests -v` (red on zero tests or no "Ran N tests" line), the benchmark's tests on the runner's own Node (red on zero tests or no "# tests N" line); job `node`, a matrix of Node 20.20.2, 22.23.3 and 24.21.0 installed from nodejs.org and checked against the SHA-256 pinned in the workflow, then "Check the Node version", the gate's tests `node --test --test-reporter=tap gate/test/*.test.js`, version printed (same guard), and "Bench numbers": `node bench/run --out "$RUNNER_TEMP/bench"`, red when its RESULTS.md has no summary line, its results.json no cases, or either differs from the committed `bench/RESULTS.md` or `bench/results.json` outside the header (`- Commit:`, `- Date:`, `- Node:`, `- Python:`; the `commit`, `date`, `node`, `python` keys); job `leak-check` - gitleaks install (official release, pinned version and SHA-256), `python3 -I scripts/leak-check` on the PR range. On `workflow_dispatch`: the same with `--all-history`.

Tests: `tests/test_ci_steps.py` - runs the tools venv, Lint, Unit tests, Gate tests, Bench tests, Bench numbers, Install Node (with a stand-in for curl) and Check the Node version `run:` blocks (and the safety-net step) as written, under `bash -e`, in throwaway directories; rejects step keys other than name, env, run; reads the Node matrix, the job timeouts and the concurrency group from the workflow's text.

Depends on: `scripts/leak-check`; `tests/`; `gate/test/`; Node release tarballs on nodejs.org (versions and SHA-256 pinned); `bench/` (its tests, `bench/run`, the committed `bench/RESULTS.md`); `ruff.toml` (ruff 0.15.8); repository secret `LEAK_PATTERNS`; `actions/checkout` pinned by commit.

Breaks: acceptance of every PR (the owner merges on green); `tests/test_ci_steps.py` (finds the steps by name).

Traps:
- touching the leak check step - PR title, body and SHAs only through `env:`, never `${{ }}` inside `run:`, otherwise command injection.
- no `LEAK_PATTERNS` secret (also every PR from a fork) - the pattern scan did not run, the step is red.
- touching checkout - keep `fetch-depth: 0`, otherwise the PR range is missing and the leak check did not run.
- touching the Lint step - keep `--no-respect-gitignore`, otherwise a `.gitignore` or `.ignore` added in any folder hides files from ruff.
- touching the Unit tests step - keep `-I` and the "Ran N tests" check, otherwise a root package named like the standard library (`unittest/`) prints a fake OK, or a run of zero tests passes.
- piping a command in a step - GitHub runs steps without a `shell:` key as `bash -e` without pipefail, so `cmd | tee` takes the exit status of `tee` and a failing run goes green.
- touching the Gate tests step - keep the zero and no-count guard: Node 22 reads a glob that matches nothing as "# tests 0" and exits 0.
- touching the Node matrix - pin each version's SHA-256 from its release's SHASUMS256.txt, keep "Check the Node version" before the tests (a `GITHUB_PATH` that did not take effect runs the runner's own Node) and keep its oldest version equal to `MIN_NODE` (`plugin.test.js`).
- touching `concurrency` - keep the PR number with the run id as the fallback: a fixed group lets another PR or a manual run cancel runs.
- touching the Bench numbers step - keep the summary and cases checks before the comparison (two files of header lines only compare equal) and compare both `RESULTS.md` and `results.json`; the header pattern must drop only the four header lines of each, or a changed number passes.
- touching the tools venv step - keep `python3 -I -m venv` run outside the checkout, otherwise a `venv.py` in the PR builds the environment whose `bin/` (fake `ruff`, `python3`) comes first on PATH for Lint and Unit tests.
- `-I` does not cover `tests/` itself: `unittest discover` puts `tests/` first on `sys.path`, so a `tests/json.py` still replaces `json` (the same open risk as an unguarded test module).
- a `# ruff: noqa` or `# flake8: noqa` comment, or a `# ruff: disable[...]` range, still hides code from ruff (open, owner decision; `--ignore-noqa` closes all three - checked by a run).
- moving the leak check into a job that runs PR tests or tools first - that code can rewrite `GITHUB_ENV` / `GITHUB_PATH` of later steps and fake the leak check; keep it in its own job.
